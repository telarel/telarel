---
title: createGenerator
description: Create a builtin generator over a fixed AST and options.
---

```ts
function createGenerator(ast: Ast, options: GeneratorOptions): Generator;

type Generator = {
    generate: () => Promise<CodeResult>;
};
```

Creates a builtin generator over `ast` and `options`.

The returned generator calls the builtin generator directly and never runs the plugin chain. When you need plugins to replace the generated result, use [generate](/apis/javascript/generate).

## Parameters

| Name      | Type               | Description                              |
| --------- | ------------------ | ---------------------------------------- |
| `ast`     | `Ast`              | The AST to generate from.                |
| `options` | `GeneratorOptions` | The generator's fixed, resolved options. |

### `GeneratorOptions`

Every field is required. In a `generate` hook, the stage options are available as `args.options`.

| Field       | Type               | Description                                      |
| ----------- | ------------------ | ------------------------------------------------ |
| `cwd`       | `string`           | Filesystem root used to resolve the source file. |
| `file`      | `string`           | The file being generated.                        |
| `sourceMap` | `SourceMapOptions` | Source-map request for the step.                 |

`cwd` anchors resolution of `file`. A relative `sourceMap.input.path` resolves against the source file's directory; absolute paths are used as-is.

The builtin generator records `file` as `map.file`. `GeneratorOptions` has no separate output name, so `file` also names the source when there is no input map.

When `ast.language` is present, generation uses it. Otherwise, generation uses the `file` extension. `GeneratorOptions` has no `language` field.

An explicit input source-map request wins over the AST's own input map when it resolves to a map. If the request is `inline` or `auto` and finds no map, the AST's own map is kept. An `external` request that cannot read its map rejects.

Standalone, `createGenerator` resolves `sourceMap.input` and applies `sourceMap.output`. In a `generate` hook, `args.options.sourceMap.input` and `sourceMap.output` are unset: the pipeline has already attached the input map to `args.ast` and applies output after the winning result. Pass `args.options` unchanged.

The returned `map` follows the applied output mode. `inline` returns no map. `external` and `both` return the map.

## Returns

A `Generator` whose `generate()` method returns `Promise<CodeResult>`:

| Field  | Type                | Description                                                          |
| ------ | ------------------- | -------------------------------------------------------------------- |
| `code` | `string`            | The generated code.                                                  |
| `map`  | `SourceMap \| null` | The source map for the generated code, or `null` when no map exists. |

Generation failures reject with a [CompileError](/apis/javascript/CompileError).

## Example

```ts
import type { AstResult, CodeResult, Generator } from "telarel";

import { createGenerator, parse } from "telarel";

const { ast }: AstResult = await parse("const x: number = 1;");

const generator: Generator = createGenerator(ast, {
    cwd: process.cwd(),
    file: "index.ts",
    sourceMap: {},
});

const result: CodeResult = await generator.generate();
```
