---
title: JavaScript plugin API
description: Implement plugins as plain objects with the JavaScript Plugin type.
---

A JavaScript plugin is a plain object with a required `name` and any subset of the eight hooks. The compiler calls the hooks present on the object. It skips hooks that are absent.

For the hook contract shared by both languages, see the [Plugin API](/apis/plugin).

## The `Plugin` type

<PeekCode>

```ts
type Plugin = {
    name: string;
    options?: ObjectHook<
        (
            ctx: CommonPluginContext,
            args: OptionsArgs,
        ) => OptionsArgs | null | void | Promise<OptionsArgs | null | void>
    >;
    start?: ObjectHook<
        (ctx: PluginContext, args: StartArgs) => void | Promise<void>
    >;
    parse?: ObjectHook<
        (
            ctx: PluginContext,
            args: ParseArgs,
        ) => AstResult | null | void | Promise<AstResult | null | void>
    >;
    prepare?: ObjectHook<
        (ctx: PluginContext, args: PrepareArgs) => void | Promise<void>
    >;
    transform?: ObjectHook<
        (
            ctx: PluginContext,
            args: TransformArgs,
        ) =>
            | TransformResult
            | null
            | void
            | Promise<TransformResult | null | void>
    >;
    finalize?: ObjectHook<
        (ctx: PluginContext, args: FinalizeArgs) => void | Promise<void>
    >;
    generate?: ObjectHook<
        (
            ctx: PluginContext,
            args: GenerateArgs,
        ) => CodeResult | null | void | Promise<CodeResult | null | void>
    >;
    end?: ObjectHook<
        (ctx: PluginContext, args: EndArgs) => void | Promise<void>
    >;
};
```

</PeekCode>

Hooks are return-based. A hook returns the new value to replace the current value, or `null` / `void` to make no change. The `start`, `prepare`, `finalize`, and `end` hooks are observers. The compiler ignores their return values.

A hook can be `async`. The pipeline resolves each hook before it continues.

## Hooks

| Hook        | Arguments                            | Return            |
| ----------- | ------------------------------------ | ----------------- |
| `options`   | `CommonPluginContext`, `OptionsArgs` | `OptionsArgs`     |
| `start`     | `PluginContext`, `StartArgs`         | `void`            |
| `parse`     | `PluginContext`, `ParseArgs`         | `AstResult`       |
| `prepare`   | `PluginContext`, `PrepareArgs`       | `void`            |
| `transform` | `PluginContext`, `TransformArgs`     | `TransformResult` |
| `finalize`  | `PluginContext`, `FinalizeArgs`      | `void`            |
| `generate`  | `PluginContext`, `GenerateArgs`      | `CodeResult`      |
| `end`       | `PluginContext`, `EndArgs`           | `void`            |

Returning `null` or `void` defers. For `parse` and `generate`, a deferral passes control to the next hook. If every hook defers, the builtin parser or generator runs. The builtin is the compiler's own parser or generator. For `options` and `transform`, a deferral keeps the current value.

### Arguments

| Type            | Fields                                   |
| --------------- | ---------------------------------------- |
| `OptionsArgs`   | `options: ResolvableOptions`             |
| `StartArgs`     | `options: ResolvedOptions` (read-only)   |
| `ParseArgs`     | `code: string`, `options: ParserOptions` |
| `PrepareArgs`   | `ast: Ast`                               |
| `TransformArgs` | `ast: Ast`                               |
| `FinalizeArgs`  | `ast: Ast`                               |
| `GenerateArgs`  | `ast: Ast`, `options: GeneratorOptions`  |
| `EndArgs`       | `error: string \| null`                  |

Every entry point uses the options bag, which always uses `sourceMap`. `parse` and `rewrite` expose a flat `inputSourceMap` at the entry point. The pipeline normalizes it to `sourceMap.input` before the `options` hook runs.

Those AST-producing entry points ignore `sourceMap.output` and `output`. A stage-agnostic plugin can set them for every stage without failing. The pipeline treats an empty `output.file` or `sourceMap.output.url` as unset, the same as absent.

The `options` hook observes the bag before the pipeline resolves it. An unset `cwd` or `file` is absent from `args.options`, so treat it as `undefined`, not `""`. A fixpoint repeats over new instances and settles when none remains. The pipeline applies the defaults (`process.cwd()` and `"index.ts"`) only after the fixpoint settles. `start` and later hooks then see the resolved values. Returning `{ ...args.options }` therefore preserves unset fields and cannot make them explicit empty strings.

The plugin object is the identity, not its `name`. The same object does not run its `options` hook again. Duplicates and the depth guard follow the [shared fixpoint rules](/apis/plugin#hook-semantics).

All hook AST values are [Ast](/apis/javascript/Ast) instances. See that page for construction, mutation, and snapshot behavior. Every AST-bearing hook receives an `Ast` whose `language` is the current grammar. A `transform` can return an `Ast` with a different language, and read-back uses the returned language. A `parse` hook replacement keeps the grammar authority of the parser options. The returned AST's language does not override the parser options.

### Errors

A hook reports failure by throwing. Throw a [PluginError](/apis/javascript/PluginError) to attach a message and an optional [ErrorSource](/apis/javascript/ErrorSource). The rejection surfaces at the entry point as a [CompileError](/apis/javascript/CompileError).

`EndArgs.error` is the rendered error text as `string | null`, not an error object.

If a stage fails and an `end` hook then fails, the `end` error replaces the stage error in the rejection.

## Ordering

`ObjectHook<T>` is either the handler itself or an object with the handler plus an `order`. `PluginOrder` is `"pre"` or `"post"`.

```ts
type ObjectHook<T> = T | { order?: PluginOrder; handler: T };

type PluginOrder = "pre" | "post";
```

A hook object stores the handler in the `handler` field:

```ts
import type { Plugin } from "telarel";

const plugin: Plugin = {
    name: "my-plugin",
    transform: {
        order: "pre",
        handler: (ctx, args) => {
            // return { ast } to replace, or null to keep the current AST
        },
    },
};
```

## Context

Every hook receives a context as its first argument.

- `options` receives `CommonPluginContext`, which has no fields.
- Every later hook receives `PluginContext`:

| Field    | Type         | Description                |
| -------- | ------------ | -------------------------- |
| `cwd`    | `string`     | Current working directory. |
| `module` | `ModuleInfo` | The module being compiled. |

`ModuleInfo` holds `file: string`, `language: Language | void`, and `sourceType: SourceType | void`.

The pipeline renders path values that are not valid UTF-8 lossily (`U+FFFD`) in hook payloads.

## Passing plugins

Callers pass plugins through the `plugins` field of the options. A `PluginOption` can be a plugin, a builtin descriptor, a falsy slot, or a nested array. An entry can also resolve to a promise.

```ts
type MaybePromise<T> = T | Promise<T>;

type FalsyPlugin = false | null | undefined;

type PluginOption = MaybePromise<
    Plugin | BuiltinPlugin | FalsyPlugin | PluginOption[]
>;
```

You can use nested arrays and falsy slots to make entries conditional:

```ts
import type { CodeResult, PluginOption } from "telarel";

import { compile } from "telarel";
import { transform } from "telarel/plugins/transform";

const isProduction: boolean = process.env.NODE_ENV === "production";

const plugins: Array<PluginOption> = [
    transform({ targets: ["es2015"] }),
    isProduction && {
        name: "check-env",
        prepare: () => {
            console.log("production build");
        },
    },
];

const result: CodeResult = await compile("const x: number = 1;", { plugins });
```

## Example

The example plugin rewrites the module specifier `react` to `preact/compat` while it walks the AST in `transform`:

<PeekCode>

```ts
import type {
    Plugin,
    PluginContext,
    TransformArgs,
    TransformResult,
} from "telarel";

import { compile } from "telarel";
import { walk } from "telarel/walker";

const FROM: string = "react";

const TO: string = "preact/compat";

const importRewrite: Plugin = {
    name: "import-rewrite",
    transform: (_: PluginContext, { ast }: TransformArgs): TransformResult => {
        ast.mutate((program): void => {
            walk(program, {
                enter(node): void {
                    if (
                        node.type === "ImportDeclaration" &&
                        node.source.value === FROM
                    ) {
                        node.source.value = TO;
                    }
                },
            });
        });

        return { ast };
    },
};

await compile('import { useState } from "react";', {
    plugins: [importRewrite],
});
```

</PeekCode>
