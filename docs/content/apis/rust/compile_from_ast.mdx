title: compile_from_ast
description: Compile an existing AST through rewrite and generation.
---

```rust
pub async fn compile_from_ast(
    ast: Ast,
    options: CompileFromAstOptions,
    plugins: Vec<SharedPluginable>,
) -> Result<CodeResult, CompileError>
```

Compiles an existing `ast` through rewrite and generation.

Because the stages run inline, the pipeline invokes each stage once per invocation. The hooks follow the shared [hook semantics](/apis/plugin#hook-semantics). The `options` hook runs once per plugin instance. The `start` and `end` hooks run per settled entry.

## Parameters

| Name      | Type                    | Description          |
| --------- | ----------------------- | -------------------- |
| `ast`     | `Ast`                   | The AST to compile.  |
| `options` | `CompileFromAstOptions` | The compile options. |
| `plugins` | `Vec<SharedPluginable>` | The plugins to run.  |

### `CompileFromAstOptions`

Every field is optional. The pipeline resolves each field against defaults before use.

| Field         | Type                       | Default                   | Description                                                                                                                 |
| ------------- | -------------------------- | ------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `cwd`         | `Option<PathBuf>`          | process working dir       | Filesystem root used to resolve relative paths.                                                                             |
| `file`        | `Option<String>`           | `index.ts`                | The file being compiled. It is used for option resolution and source-map defaults. It does not change the AST grammar.      |
| `language`    | `Option<Language>`         | AST language, then `file` | The grammar recorded in the resolved step options and visible to plugins. It does not change the input AST grammar.         |
| `source_type` | `Option<SourceType>`       | inferred                  | The module kind recorded in the resolved step options and visible to plugins. It does not change the input AST module kind. |
| `output`      | `Option<OutputOptions>`    | `file`                    | Output code configuration. `output.file` derives the default source-map URL.                                                |
| `source_map`  | `Option<SourceMapOptions>` | off                       | The source-map inputs and outputs requested for the run.                                                                    |

The explicit values are visible to the `options` hook. After resolution, the explicit or inferred values are visible to `start` and later hooks. They are available through the resolved options and `PluginContext.module`.

When `language` is omitted, the resolved language falls back to the input AST grammar, then the file extension. `compile_from_ast` does not reparse the AST. The rewrite stages return the input AST or a plugin replacement. Builtin generation emits from that AST's own `Program.source_type`.

## Returns

`Result<CodeResult, CompileError>`, where `CodeResult` is `{ code: String, map: Option<SourceMap> }`.

## Example

```rust
use telarel::{
    parse,
    compile_from_ast,
    ParseOptions,
    CompileFromAstOptions,
    AstResult,
    CodeResult,
};

let parsed: AstResult = parse(
    String::from("const x: number = 1;"),
    ParseOptions::default(),
    vec![],
).await?;

let result: CodeResult = compile_from_ast(
    parsed.ast,
    CompileFromAstOptions::default(),
    vec![],
).await?;

println!("{}", result.code); // const x: number = 1;
```
